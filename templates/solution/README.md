## Quick start

```bash
dotnet tool install -g TPLTOOL   # install the jex CLI once
jex check                       # format + build + test (the acceptance command)
jex run                         # start the API: http://localhost:5208 , Scalar UI: /scalar
```

On first run in Development the tables are created automatically and an administrator `admin@example.com / Admin123!` is seeded (see `src/Jex.WebAPI/appsettings.Development.json`).
`src/Jex.WebAPI/Jex.WebAPI.http` logs in and calls the sample endpoints directly.

`jex` works from any subdirectory of the solution; it finds this project through the `jex.json` at the root (the file records the template version the project was generated with, so commit it).

## Layout

```
src/
  Jex.Domain/           entities, enums, constants, domain events
  Jex.Application/      commands/queries + handlers, validators, pipeline behaviours, interfaces
  Jex.Infrastructure/   FreeSql repositories and configurations, Identity stores, migrations, health checks
  Jex.WebAPI/           endpoint groups, envelope, authentication/authorization, startup
<!--#if (UseAspire) -->
  Jex.AppHost/          .NET Aspire orchestration
<!--#endif -->
  Jex.ServiceDefaults/  OpenTelemetry, service discovery, resilience
tests/
  Jex.UnitTests/  Jex.IntegrationTests/  Jex.ArchitectureTests/
db/migrations/          versioned SQL migrations (generated by jex db script, applied by jex db migrate)
docs/decisions/         architecture decision records (ADRs)
openapi.json            API contract generated at build time
jex.json                jex project marker and the template version used to generate it
```

Sample feature slice: `TodoLists` / `TodoItems` (entity → repository → use cases → endpoints → tests). Model new features on it.

## Common commands

| Purpose | Command |
|---|---|
| Acceptance gate | `jex check` |
| Scaffold a feature | `jex scaffold feature Order Orders` |
| Generate a migration script | `jex db script add-orders` |
| Apply migrations | `jex db migrate` |
<!--#if (IncludeDocker) -->
| Local database container | `jex infra up` / `jex infra down` |
| Build the image | `docker build -f src/Jex.WebAPI/Dockerfile -t TPLNAMELOWER .` |
<!--#endif -->
<!--#if (UseAspire) -->
| Run with Aspire | `jex run --aspire` |
<!--#endif -->

`jex db migrate` targets a database managed only by migrations. The development database is created by `Database:AutoSyncStructure` and has no migration history, so migrations fail against it; to try migrations locally, clear it first (SQLite: `jex db reset`).

## Configuration

- Secrets stay out of the repository: provide `Jwt:Secret`, `Seed:Admin:Password` and the like through environment variables or `dotnet user-secrets`. The development secrets in `appsettings.Development.json` are generated by the template and are for local use only.
- Database: `ConnectionStrings:DefaultConnection` and `Database:Provider`; in production `Database:AutoSyncStructure` must be `false` (ADR-0008).
- CORS, rate limiting, seeding, migrations: see the matching sections of `appsettings.json`; they are validated at startup.

## Removing the sample feature

Delete `src/*/**/Todo*`, `src/Jex.WebAPI/Endpoints/Todo*.cs`, `tests/**/Todo*` and `src/Jex.Infrastructure/Persistence/Configurations/TodoConfigurations.cs`, then run `jex check`.
